# 1401 中文汉化版 · 使用说明书

> 对应版本：官方 1401 v2.9 ｜ 适用：OpenCore 黑苹果，macOS 15.5 及以上（含 macOS 26 Tahoe）

## 一、这是什么

1401 是 NullMoth 官方提供的工具，用来在 OpenCore 黑苹果上安装、更新和移除 NVIDIA（NullMoth）驱动。本汉化版以翻译界面文字为主，另新增「使用说明」与「AI 日志解析」两个页面；驱动安装逻辑、驱动文件与校验方式均与官方完全一致。

- 汉化范围：主界面五个页面、驱动设置窗口（19 项设置）、EFI 检查规则（27 条）、窗口标题、全部按钮与提示
- 本包**不含驱动本体**：驱动由 app 运行时从官方源下载，并对照官方 SHA-256 校验
- 许可证：PolyForm Noncommercial 1.0.0，仅供非商业用途免费使用；与 NullMoth 官方无隶属关系
- Required Notice: Copyright NullMoth Systems

## 二、第一次打开

1. 推荐下载 `1401-zh-CN-2.9.dmg`：双击打开，把 `1401汉化.app` 拖到右侧「应用程序」文件夹；若下载的是 `1401-zh-CN-2.9.zip`，用访达解压后同样把 app 拖进「应用程序」
2. 首次打开若提示「无法验证开发者」：右键点 app → **打开**；或到 系统设置 → 隐私与安全性 → 点「仍要打开」（app 为 adhoc 自签名，与官方分发方式相同）
3. **动手之前先备份 EFI**：到「工具 · 挂载 EFI」挂载引导分区，把整个 EFI 文件夹复制到 U 盘
4. 保持引导本机启动的 U 盘或硬盘（OpenCore 所在盘）始终插在电脑上，1401 要改的就是那上面的配置

## 四、驱动安装四步（「本机」页）

1. **获取驱动** —— 下载官方驱动包并校验哈希
2. **先看清楚再动手** —— 列出将要改动的每一处，此步不写入任何内容（macOS 会要求输入密码）
3. **安装** —— 自动备份 OpenCore 配置，只执行清单内的改动，并在启动菜单加入 `1401: Remove NVIDIA driver`
4. **重启** —— 若系统提示扩展被阻止，到 系统设置 → 隐私与安全性 点「允许」，再重启一次

## 五、驱动设置窗口

从主界面进入「驱动设置」，共 19 项，分「显示」「性能」两组：

- **显示**：HDR10、10 位色深、可变刷新率、输出色深 / 颜色格式 / 动态范围、数字振动、动态超级分辨率、HiDPI 模式、旋转缩放、环视多屏、笔记本面板亮度
- **性能**：帧率上限、低延迟模式、着色器缓存上限、多张 N 卡、为应用指定显卡、内置按应用配置、系统内存保留

使用要点：

- 每项改动都会**先展示将要写入的内容并请求确认**，确认后才写入
- 下拉选「默认」表示交给驱动自行决定；「开启 / 关闭」为显式设定
- **显示类设置属于引导参数，重启后生效**；改动前请确认自己能进系统
- 不确定某项作用时，把鼠标停在说明文字上读一遍，保持「默认」最安全

## 六、实验性驱动与功能（逐项说明）

位置：「本机」页往下拉，共 **14 个复选框**，上方是「全选 / 全不选」，底部是「应用」。官方明确说明这些功能**均为离线编写与测试，尚未在所有机型上验证**，默认全部关闭——开启它们等于主动替官方做实机测试。

### 怎么用

1. **先备份 EFI**（见第二节），并确保能进入 OpenCore 启动菜单
2. **一次只勾一项**，然后点「应用」（需要管理员密码）。「全选 / 全不选」**只改变勾选框**，不点「应用」不会写入任何东西
3. **重启才生效**。重启后确认内屏、外接屏、睡眠唤醒、常用软件都正常，再考虑开下一项
4. 有异常就把勾取消、再点一次「应用」并重启，即可**完全还原**；你自己手动设置的参数永远不会被移除

**点「应用」后改了什么**：把选中的标志写入 `/Library/NullMoth/experimental`（例如 `ON=igpuproxy`），驱动启动时读取；键盘背光、显示音频这类还会让 OpenCore 注入对应 kext，个别项会往 boot-args 追加参数（「内屏走核显」对应 `nvfbigpu=1`）。想确认当前开了哪些，直接查看这个文件即可。

> **风险**：这些开关直接改动驱动的电源管理、显示路径与 Metal 功能实现，最坏情况是黑屏、屏幕冻结、卡死或驱动加载失败。务必保留 `-v` 启动参数，**别一次全开**——多项叠加出问题就无法定位是谁导致的。**不建议点「全选」。**

### A. 笔记本与显示相关（6 项）

| 项目 | 开启后会怎样 | 建议 |
|---|---|---|
| **内屏走核显** `igpuproxy` | 混合输出笔记本的内屏物理接在核显 / 集显上，开启后驱动用「代理显示头」把内屏呈现出来，内屏才有画面；通常还会追加 `nvfbigpu=1` 引导参数，属于会动 EFI 的项目 | 内屏接核显的双显卡笔记本（Optimus 机型）**应保持开启**；台式机、内屏直连 N 卡的机器不用开 |
| **键盘背光** `kbl` | 让亮度按键调节笔记本键盘背光（NMKbdBacklight kext）。点「应用」会让 OpenCore 启用这个原本默认关闭的 kext，需要 VirtualSMC；2.9 构建的 EFI 已自带，旧 EFI 会从已装驱动里复制 | **可以试但别抱期待**：官方注明「尚未在笔记本上实测」，不同品牌背光由 EC / 厂商固件控制，很可能无效或让亮度键行为异常。要开就单独开这一项验证 |
| **键盘背光（HID 通道）** `kblhid` | 部分笔记本的背光走 HID 通道，作用与上一项相同，**必须先开启「键盘背光」**才有效 | 只在「键盘背光」开了却没反应时再试；单开它无效 |
| **NVIDIA 显示音频** `hda` | 把 N 卡的 HDMI / DisplayPort 音频交给 Apple HD Audio 驱动输出，音量滑块与静音可用（NMHDA kext，由 OpenCore 加载）。**仅限 macOS 15**；macOS 26 改用 NMXAudio | 只有在 macOS 15 且确实要把声音从外接显示器 / 功放输出时才有意义；macOS 26 用户**不用开**，没接 HDMI/DP 也不用开 |
| **笔记本 GPU 功耗上限** `tgp` | 接电源时允许 N 卡跑满平台完整功耗上限（Dynamic Boost），用电池时自动放开限制 | 接电源玩游戏 / 跑渲染**可以试**，换来更高帧率，代价是功耗与发热上升、风扇更响；只在意续航就别开 |
| **混合输出笔记本：最新 Intel 显卡** `hybrid20` | 让混合面板驱动在 Lunar Lake / Panther Lake 这些新 Intel 核显上正常唤醒；仅在混合笔记本模式开启时有关，代码依据 Linux 显示驱动编写，官方注明尚未在该硬件上跑过 | **只有这些新 Intel 平台才适用**；AMD 平台、老 Intel 核显、台式机开了也没用，别开 |

### B. 省电与稳定性（2 项 · 风险最高）

| 项目 | 开启后会怎样 | 建议 |
|---|---|---|
| **空闲 GPU 深度休眠** `rtd3` | N 卡空闲时进入最深的省电状态（runtime D3）。官方说功耗收益与唤醒表现还要先在工作室机器上测量才敢推荐 | **不建议开**：省下的电有限，但可能出现睡下去唤不醒、唤醒黑屏、驱动掉卡，排查起来也难 |
| **空闲链路省电** `aspm` | 空闲时让 N 卡与主板的 PCIe 链路进入 ASPM L1 休眠，两端都支持才生效。驱动默认保持固件设定的链路状态，因为在未针对此设计的主板上链路休眠**可能导致卡死或掉卡** | **不建议开**：如果开了以后空闲时屏幕冻结，第一件事就是把它关掉 |

### C. 图形与性能（6 项）

| 项目 | 开启后会怎样 | 建议 |
|---|---|---|
| **硬件光线查询** `hwrt` | 用 NullMoth 自建的加速结构，在 N 卡的 RT 核心上执行光线查询，让支持 Metal 光追的应用获得硬件加速 | 有 RT 核心的卡（Turing 及以后）且确实要跑光追应用时**可以试**；属于实验实现，可能画面错误或崩溃，普通桌面使用没必要开 |
| **光线追踪中的曲线图元** `curves` | 让光线查询支持曲线图元，但走的是**软件遍历、速度较慢**，需配合上一项 | 除非某个应用明确报「缺曲线图元」，否则**不用开**，开了只会更慢 |
| **Metal 瓦片着色** `tile` | 为使用瓦片着色（tile shader）特性的应用启用该能力 | 只对用到该特性的少数应用有效，桌面与多数游戏无感；不确定就**保持关闭** |
| **GPU 编码的命令列表** `icb` | 启用由 GPU 写入的间接命令缓冲（indirect command buffer），供特定渲染 / 计算应用使用 | 收益只出现在特定应用；实验性实现，遇到渲染异常先关它 |
| **AMD / Intel 视频解码** `xvt` | 在 AMD 与 Intel GPU 上启用 AV1、VP9 硬件解码 | 核显本身要支持对应格式才有意义（老核显没有 AV1 硬解）；播放 4K / AV1 视频遇到问题可以试，否则保持关闭 |
| **游戏 GPU 优先级** `gameprio` | 提高游戏在 GPU 调度中的优先级，让游戏更容易抢到显卡资源 | 相对温和、**可以试**；效果依负载而定，后台还在跑渲染 / 转码时更明显 |

## 七、装好驱动后的常见情况

- **显卡名称或显存显示奇怪**：系统信息里的名称/显存由驱动注入，名称不标准不代表驱动没工作
- **Optimus 双显卡笔记本**：内屏通常由核显驱动，外接 USB-C / HDMI 才直连 N 卡，这是正常形态；若内屏无画面，检查第六节的「内屏走核显」
- **保留 `-v` 详细启动模式**：方便看启动报错，不必去掉
- **Lilu / AMFIPass 相关报错**：先确认 kext 版本配套、SIP（`csr-active-config` 常为 `0x0FFF`）、SecureBootModel 等设置
- **不要随意屏蔽核显或其他显卡**，除非明确知道后果
- 驱动下载需要联网；网络不通时先检查系统代理设置

## 八、汉化版专属注意事项（重要）

- **应用更新已指向本汉化版的发布页**：「本机」页的「查看汉化版更新」会打开 https://github.com/huangjinkun2006/1401/releases/latest；官方应用自更新已停用，界面不会再被覆盖回英文。**驱动更新仍走 NullMoth 官方**（驱动包带官方签名），「检查驱动更新 / 更新驱动」可照常使用
- 若按仓库 `zh-CN/mac-resources/` 自行替换资源文件来汉化，设置窗口**标题栏**仍是英文 `Driver settings`（标题写在可执行文件里），不影响使用
- 本汉化不触碰驱动、kext、EFI 内容，也不改任何校验逻辑

## 九、出问题怎么办

1. 先看「问题检查」页给出的规则说明和修复步骤
2. 重启时保留 `-v`，观察启动日志定位失败点；刚开过实验性开关的，先取消勾选 → 应用 → 重启还原
3. 把日志贴进左侧「AI 日志解析」页，先看离线中文诊断结论，再决定要不要交给 AI 通读
4. 用「工具 · 挂载 EFI」把之前备份的 EFI 还原回去
5. 启动菜单里的 `1401: Remove NVIDIA driver` 可一键移除驱动
6. 需要官方协助时用「发送报告」（自愿上传）

## 十、AI 日志解析（汉化版新增）

左侧栏「AI 日志解析」是汉化版额外提供的排障助手，官方原版没有。支持粘贴、拖入或选择 `.log` / `.txt` / `.ips` / `.panic` 文件（可多选），日志来源包括 -v 启动滚屏、panic 崩溃报告、OpenCore 日志、`log show` 输出、1401 四步安装日志。

**本地智能解析（默认、离线）**：点「本地智能解析」立即得到中文报告 —— 概览（日志类型、有效行数、命中规则数、风险等级）、每条问题的原文证据 + 原因解释 + 修复步骤，以及关键线索（macOS / 内核版本、boot-args、kext 列表、显卡相关行、本机检测信息）。规则库覆盖 panic、Lilu / kext 加载失败、签名校验、显卡被屏蔽、Optimus / igpuproxy、GPU 初始化、ACPI、OpenCore 配置、Above 4G / 可变 BAR、下载与权限等 20 多类常见模式。**本地解析完全离线，不联网、不上传，日志不会离开这台电脑。**

**AI 深度分析（可选）**：

- 方式 A：在「接口设置」里选服务商预设（DeepSeek / 通义千问 / Kimi / OpenAI / 本机 Ollama / 自定义），填接口地址、模型名与自己的 API Key，点「AI 深度分析」。使用 OpenAI 兼容的 `chat/completions` 协议。
- 方式 B（推荐、任何环境都能用）：点「复制 AI 提示词」，再点「打开 AI 网页」粘贴到任意大模型对话。提示词已包含本机信息、本地诊断摘要和裁剪后的日志（过长时保留开头、报错附近与结尾）。

> 多数云端大模型接口不允许从本地网页直连（CORS），遇到「直连被拦截」提示请改用方式 B；本机 Ollama 用 `http://127.0.0.1:11434/v1`，必要时设置 `OLLAMA_ORIGINS=*` 并重启 Ollama。API Key 只保存在本机 localStorage，点「清除设置」即可删除；**只有主动点 AI 分析时才会联网**，且只发往你自己填写的服务商。

AI 结论只作排障参考，不是官方诊断；改 EFI 前务必备份，并保留 `-v`。
