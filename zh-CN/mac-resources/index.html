你的 Mac，一目了然

1401 为运行 macOS 15.5 或更高版本（含 macOS 26 Tahoe）的 OpenCore 黑苹果安装 NullMoth 驱动。请保持引导本机启动的 U 盘或硬盘（OpenCore 所在盘）始终插在电脑上：1401 要改的就是那上面的设置。

操作流程

  1. 获取驱动。
  2. 先看清楚再动手。 1401 会读取你的 OpenCore 配置，并列出它要做的每一处改动。此步不会改任何东西。（macOS 会要求输入密码。）
  3. 安装。 自动备份你的 OpenCore 配置，只执行清单中列出的改动，安装驱动，并在启动菜单里加入 1401: Remove NVIDIA driver。
  4. 重启。 如果 macOS 提示系统扩展被阻止，打开 隐私与安全性，点「允许」，然后再重启一次。

更新


1401 会检查最新的 NullMoth 驱动和最新的 1401 应用。应用会自我更新并重新打开；驱动则按上面的流程下载、对照官方 SHA-256 校验后安装，且安装前会先备份你的 OpenCore 配置。


   


抢先更新。 新驱动会先推送给开启此选项的用户，等他们的机器确认没有问题后再向所有人开放。开启后可提前一两天拿到新版本，并在出现异常时提交日志。


  



升级到 macOS 26 Tahoe


在 macOS 15 上，为本机准备 Tahoe 会安装或更新驱动、将其挂起（park），并给安装器提供屏幕点亮所需的小容量 GPU BAR 设置。之后从「软件更新」安装 macOS 26；更新后的首次开机会自动完成驱动的 Tahoe 适配并自行重启一次。取消 Tahoe 准备 则会还原全部改动。


   



如果重启后出了问题


在 OpenCore 启动菜单中选择 1401: Remove NVIDIA driver，再选你的 macOS 磁盘。1401 会卸载驱动并重启，本机将恢复到安装前的状态（包括 OpenCore 配置）。在第二次重启之前屏幕可能保持黑屏。









检查我的 EFI


对照与你机型相同/相近的机器验证过的配置，检查本机启动所用的 OpenCore 设置，并解释需要修改的地方及具体步骤。只读不写：不会改动任何东西。会要求输入一次密码。













工具


挂载 EFI


EFI 分区保存着你的引导设置。1401 会找到本机启动所用的那个分区，挂载并在访达中打开它。会要求输入一次密码。


 


启动文字（verbose 模式）


开机时显示 macOS 的启动过程细节，而不是只有苹果标志。排查启动卡住时有用。下次重启后生效。


 


内建屏幕亮度（笔记本）


适用于内屏直连 NVIDIA GPU 的笔记本（MUX 已设为 Discrete 或 dGPU）。开启后驱动可从笔记本固件读取面板的亮度控制。默认关闭，因为该调用曾导致部分机器在 GPU 启动时卡住；如果你也卡在那里，请在启动菜单选 1401: Start once without NVIDIA driver，然后在这里把它关掉。


 


HiDPI（Retina）分辨率模式


让 HiDPI「看起来像」分辨率可用，例如在 2560x1440 屏上使用 1920x1080，包括用 BetterDisplay 等工具添加的自定义分辨率。不开启时这类分辨率会被拒绝并弹回。开启后驱动会以最高两倍于屏幕的尺寸绘制桌面，会占用更多显存。下次重启后生效。


 


自动登录


驱动缺失期间，1401 开启了自动登录以便本机能进入桌面。这会把你的密码以可被任何能读取磁盘的人还原的形式存储。驱动正常工作后，请关闭它。




混合输出笔记本（内屏由 Intel 或 AMD 处理器显卡驱动）


多数游戏笔记本把内屏接在处理器显卡上，NVIDIA 卡没有可绘制的屏幕。此功能会在 NVIDIA 驱动旁安装一个面板驱动（Intel 显卡用 Intel 版，带 Radeon 显卡的 Ryzen 用 AMD 版）：NVIDIA 负责渲染，渲染完的每一帧经处理器显卡送到屏幕。Ryzen 笔记本需先关闭 OpenCore 的 Fix PAT 补丁（见 docs/HYBRID-LAPTOPS.md，仅英文版）。复制（copy）方式适用于 Intel 第 11 代及更新；原位扫描输出（scan out in place）是第 12、13 代上更快的等级。此功能尚未在混合输出笔记本上实测，你的「发送日志」就是帮它完善的方式。它需要 NVIDIA 驱动已安装，且上方已校验驱动包。


如果屏幕保持黑屏，请在启动菜单选 1401: Start once without NVIDIA driver，然后在这里关闭。关闭时会一并移除面板驱动。


   


位于 Intel VMD 或 RAID 之后的硬盘


macOS 只能使用固件以普通 AHCI 或 NVMe 磁盘形式呈现的硬盘。这台机器使用 Intel VMD 或 RAID 存储控制器，内置硬盘可能因此对 macOS 隐藏。两种绕过办法：


安装到外置硬盘。 插上 USB SSD（或不在 VMD 之后的 SSD），从 1401 U 盘把 macOS 装上去。内置硬盘和 Windows 不会被动到。在 1401 for Windows 中，构建前勾选 Install macOS on an external drive。


关闭 VMD。 1401 for Windows 在构建时会显示你主板的 BIOS 设置路径，并提供 Prepare Windows、Finish 和 Undo 三个选项：Prepare 创建还原点、暂停 BitLocker 并设置标准驱动；随后你在 BIOS 中关闭 VMD；Finish 让 Windows 恢复正常启动；Undo 把每个值改回原样。这些步骤只能在 Windows 上执行，所以本应用只作说明。

GPU 加速（boost）


开启期间将 NVIDIA 卡锁定在最高频率，适合受 GPU 空闲到繁忙爬升限制的工作负载。代价是功耗和发热，所以在你手动开启前保持关闭。它会从已校验的驱动包安装一个小型后台任务；任何以 root 运行的内容之前都会先校验包内文件清单。关闭即停止锁频；「移除」则把任务从本机删掉。


    


Ryzen 笔记本功耗配置


Ryzen 笔记本默认按处理器出厂功耗上限运行，用电池时又吵又热。此功能通过 NullMoth 的 RyzenAdj 构建设置一组更安静的配置（默认持续 13 W、慢速 14 W、快速 15 W、70 °C；开启前可在下方修改数值）。它会安装一个只有在开启后才能与处理器电源控制器通信的小内核扩展，以及一个以 root 运行的任务。在你选择开启前保持关闭。


如遇异常，在这里关闭即可：这会移除后台任务、内核扩展和引导设置。

AMD / Intel GPU 与 NPU 驱动（测试版）


适用于 macOS 没有驱动的 AMD 和 Intel GPU（Ryzen APU、Radeon RX 7000/9000、Intel Iris Xe 与 Arc 显卡），以及 Intel Core Ultra 和 AMD Ryzen AI 处理器中的 NPU。早期测试版本：你的「发送日志」就是帮它完善的方式。它只从 linux-firmware 下载你的 GPU 和 NPU 所需的固件（逐个文件校验），下次重启后生效。


如果这块 GPU 正在驱动你的屏幕，屏幕可能保持黑屏。此时请在启动菜单选 1401: Start once without NVIDIA driver（它也会挂起这个驱动），然后在这里关闭。


 


测试计划。 测试驱动开启期间，每次重启后 1401 会发送一份简短报告：驱动的内核消息、崩溃记录（如有）以及你的 GPU 和构建版本（已去除名称与序列号）。可随时退出。


  


Intel Xe 显卡（WhateverXe，测试版）


适用于 macOS 15.8 或 26.7 及以上版本的 Tiger Lake、Alder Lake 和 Raptor Lake Intel 显卡。使用 b00t0x 的 WhateverXe：1401 把它加入 OpenCore，你重启后再次点击 开启 即可安装其显卡组件包。组件直接来自作者的 GitHub，逐个校验。开启期间 WhateverGreen 会被停用；关闭会还原所有改动。


如果重启后屏幕保持黑屏，请在启动菜单选 1401: Start once without NVIDIA driver：该次启动同样会停用 WhateverXe。然后在这里关闭。


 


游戏模式


当游戏位于前台并全屏时，优先把处理器让给游戏、限制后台索引和其他应用占用显卡，退出游戏后全部还原。开启期间菜单栏会出现一个手柄图标。开启前保持关闭，关闭即移除。


  


麦克风与摄像头


装上驱动后，macOS 不会在应用使用麦克风或摄像头前征询许可，导致 Discord 之类的应用只收到静音，也从不出现在「隐私与安全性」里。在这里选择应用，授权其使用麦克风、摄像头和屏幕录制。


 


驱动设置


HDR、10-bit 色彩、可变刷新率、色彩范围、缩放、环绕、帧率限制等设置，并显示 GPU 的链路与显存信息。每处改动都会完整展示并先征得确认。




GPU 画像（实验性）


对本机 GPU 进行几分钟的测量：Metal 报告了什么、正确性检查、显存与算力速度，以及若干测试着色器。不改动任何东西，也不触碰显示模式。结果保存在日志文件夹，「发送日志」会一并上传，让下一版驱动能针对你的显卡调优。

还有问题？


发送日志


1401 会发送它做过的操作、驱动状态、崩溃报告、OpenCore 启动日志和数值化设备映射，并已去除名称、序列号和地址。你会得到一个报告 ID，可贴到 NullMoth Discord 求助。


如果驱动无法转译某个着色器，最多 24 个这样的着色器（每个包最多 4 MB，来自你运行过的应用）会随报告附上，以便复现问题。只有你按下按钮才会发送。不想让驱动保留它们，可创建空文件 /Library/GPUBundles/nvmtl/no-failed-air。


 


记录闪烁：屏幕闪烁时按下它。1401 会记录 20 秒驱动向显示器送帧的过程，并随日志一起发送。




崩溃报告


如果驱动导致本机崩溃，1401 会在下次登录时询问是否生成报告。它是你桌面上的一份文本文件，包含硬件信息和故障详情，且已去除你的姓名、Mac 名称、序列号、地址和文件路径。1401 绝不会自行发送它。




   


可选诊断


此版本中捕获功能不可用。「发送日志」仍会收集硬件、内核与恐慌（panic）证据。安全设置没有任何变化。


 


检查可用性不会启动任何采集。已保存的回执需要其独立的会话上传权限和一次单独的「发送日志」确认。
